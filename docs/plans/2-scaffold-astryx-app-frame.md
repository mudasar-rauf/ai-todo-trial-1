# Technical Plan: #2 Scaffold the app: an Astryx-themed frame with a header and a main region

**Ticket:** #2   **Spec:** [docs/specs/2-scaffold-astryx-app-frame.md](../specs/2-scaffold-astryx-app-frame.md)   **Status:** Draft

## 1. Summary

Create the project from nothing: a Vite 8 + React 19 + TypeScript app styled with Astryx's prebuilt CSS and `@astryxdesign/theme-neutral`, with ESLint, Vitest and Playwright set up and the five scripts CI runs. The page is Astryx's `AppShell`: its top area (a `TopNav` showing the app name) is the banner landmark, and its content area is the main landmark, left empty for the task screen. We use Astryx's prebuilt path (CSS imports plus `<Theme>`), not the StyleX source build, so there are no build plugins. All dependencies a todo screen will need are installed now, so later issues don't touch `package.json`.

### Non-functional requirements
- CI runs Node 24 on ubuntu-24.04 and installs only Chromium (`npx playwright install --with-deps chromium`). Playwright must use only the `chromium` project.
- The page requests nothing from outside the app: fonts come from `@astryxdesign/theme-neutral/fonts.css`, which ships the font files.

### Out of scope
The task screen and every feature; `.github/workflows/`.

### Assumptions
- **App name:** "Todo". It lives in one constant (`src/appName.ts`), so renaming it is a one-line change.
- Astryx's font for theme-neutral is **Figtree** (its README says "Figtree typography"; it is shipped by `fonts.css`).

## 3. Current state

The repository has only `README.md`, `.factory/workflow.yaml` and `.github/workflows/ci.yml`. There is no `package.json`, so CI fails today. CI runs, in order: `npm ci`, `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npx playwright install --with-deps chromium`, `npm run test:e2e`.

Verified in the published packages (version 0.7.17, read from the npm tarballs):
- `@astryxdesign/core` peer-depends on `react >=19`, `react-dom >=19`, `@stylexjs/stylex ^0.19.0`. It exports `./reset.css`, `./astryx.css`, `./theme` (the `Theme` provider), `./AppShell` and `./TopNav`.
- Its README's Vite setup: install `@astryxdesign/core @astryxdesign/theme-neutral @stylexjs/stylex`, then import four stylesheets **in this order**: `@astryxdesign/theme-neutral/fonts.css`, `@astryxdesign/core/reset.css`, `@astryxdesign/core/astryx.css`, `@astryxdesign/theme-neutral/theme.css`, and wrap the app in `<Theme theme={neutralTheme}>` (`neutralTheme` from `@astryxdesign/theme-neutral/built`). No build plugins.
- `AppShell` renders its header area (`topNav` + `banner` slots) with `role="banner"` and its children in a content area with `role="main"`. `TopNav` takes a `heading` prop, e.g. `heading={<TopNavHeading heading="My App" />}`.
- `typescript-eslint` 8.x peer-depends on `typescript >=4.8.4 <6.1.0`, so TypeScript must stay on 6.0.x (7.0 is out but not supported by the linter).

## 4. Proposed design

### Overview
```
index.html ─ #root ─ src/main.tsx
                       imports src/index.css (4 Astryx stylesheets, in order)
                       renders <StrictMode><App/></StrictMode>
src/App.tsx:  <Theme theme={neutralTheme}>
                <AppShell topNav={<TopNav heading={<TopNavHeading heading={APP_NAME}/>}/>}
                          mobileNav={false}>
                  {/* the task screen mounts here (later issue) */}
                </AppShell>
              </Theme>
```

### Scripts (contract, AC4)
```json
{
  "dev": "vite",
  "typecheck": "tsc -b --noEmit",
  "lint": "eslint .",
  "test": "vitest run",
  "build": "vite build",
  "preview": "vite preview",
  "test:e2e": "playwright test"
}
```
`build` is `vite build` only; type checking is `typecheck`'s job (CI runs it first). If `tsc -b --noEmit` misbehaves with project references, use `tsc -p tsconfig.app.json --noEmit && tsc -p tsconfig.node.json --noEmit`; either way, no files are emitted.

### Dependencies (AC6)
- `dependencies`: `react`, `react-dom` (^19), `@astryxdesign/core`, `@astryxdesign/theme-neutral` (pin both **exactly** to the same version, 0.7.17 or the current one; theme-neutral peer-depends on core at an exact version), `@stylexjs/stylex` (^0.19).
- `devDependencies`: `vite` (^8), `@vitejs/plugin-react`, `typescript` (`~6.0`), `@types/react`, `@types/react-dom`, `@types/node`, `eslint`, `@eslint/js`, `typescript-eslint`, `eslint-plugin-react-hooks`, `eslint-plugin-react-refresh`, `globals`, `vitest`, `jsdom`, `@testing-library/react`, `@testing-library/dom`, `@testing-library/user-event`, `@testing-library/jest-dom`, `@playwright/test`.
- Not `@astryxdesign/build`, nor the StyleX Babel/unplugin packages: the prebuilt path needs none.
- `npm install` must finish with no peer-dependency errors and without `--legacy-peer-deps` (CI's `npm ci` has no flags). If one peer range blocks this, choose the newest version that fits, don't override it.

### Playwright (AC3, AC5)
- `webServer: { command: 'npm run dev -- --port 5173 --strictPort', url: 'http://localhost:5173', reuseExistingServer: !process.env.CI }`, `use.baseURL` the same.
- `projects: [{ name: 'chromium', use: devices['Desktop Chrome'] }]` only.
- `forbidOnly: !!process.env.CI`, `retries: process.env.CI ? 1 : 0`.

### ESLint
Flat config: ignore `dist`, `playwright-report`, `test-results`; `@eslint/js` recommended + `typescript-eslint` recommended for `**/*.{ts,tsx}`; `react-hooks` and `react-refresh` (Vite template defaults); browser globals for `src`, node globals for config files and `e2e`.

### Error handling and edge cases
- `AppShell` has a mobile nav that it fills from `sideNav`; there is none, so pass `mobileNav={false}` so no empty drawer toggle appears at narrow widths.
- `AppShell` defaults `height: 'fill'` (the main area scrolls inside the viewport), which suits a single-screen todo app. Keep the default.
- Keep `TopNav`'s `<nav>` landmark if it renders one: the criterion counts banner and main only.

### Security, performance, observability
Nothing applies beyond keeping fonts local (see non-functional requirements).

## 5. Key decisions
| Decision | Choice | Rationale | Alternatives rejected |
|---|---|---|---|
| How Astryx is built | Prebuilt CSS + `/built` theme | Astryx's README for Vite: "No build plugins needed"; fewest moving parts | StyleX source build via `@astryxdesign/build` (more config, Babel plugins; only needed for custom StyleX in app code) |
| Frame component | `AppShell` + `TopNav` | Gives the banner and main landmarks, theme spacing and the skip-link target; the app follows Astryx's own page layout | Hand-written `<header>`/`<main>` (duplicates Astryx and its spacing, which AC2 wants from the theme) |
| TypeScript version | `~6.0` | `typescript-eslint` supports `<6.1.0` | 7.0 (breaks `npm ci`'s peer check with typescript-eslint) |
| E2E server | `vite` dev server | AC1 is about `npm run dev`; fast; no build needed first | `vite preview` (would also work, but tests a different path from AC1) |
| Unit test environment | jsdom | Testing Library standard; Vitest supports it | happy-dom (fine, but less common with Testing Library) |

No decision needs an ADR.

## 6. Implementation tasks

### T1. Project, tooling and scripts (M)
- Goal: a project where all five scripts run.
- Changes: `package.json`, `package-lock.json`, `tsconfig*.json`, `vite.config.ts`, `eslint.config.js`, `playwright.config.ts`, `.gitignore`, `index.html`, `src/vite-env.d.ts`, `src/test/setup.ts`.
- Details: as in section 4. Generate the lockfile with `npm install`, on Node 22.12+ / npm 10; don't hand-edit it. Do not copy Vite's demo assets (`src/assets`, `public/vite.svg`, `App.css`, counter).
- Done when: `npm ci` from a clean `node_modules` succeeds with no flags; each script exists (AC4, AC5, AC6).
- Tests: none of its own; T2 and T3 put tests in place.
- Depends on: none.

### T2. The Astryx frame (S)
- Goal: the themed page with a header holding the app name and an empty main region.
- Changes: `src/main.tsx`, `src/index.css`, `src/App.tsx`, `src/appName.ts`, `src/App.test.tsx`.
- Details: the import order in `index.css` matters (it maps to Astryx's cascade layers). Leave a comment in the main region where the task screen mounts. Show the app name as a heading via `TopNavHeading`.
- Done when: `npm run dev` shows the name in the top bar and an empty themed content area; no Vite demo content (AC1, AC2).
- Tests: `src/App.test.tsx` renders `<App/>` and asserts one `banner` with the app name in it and one `main` (`getAllByRole(...).toHaveLength(1)`).
- Depends on: T1.

### T3. End-to-end test of the frame (S)
- Goal: Playwright checks AC1, AC2 and AC3 in a real browser.
- Changes: `e2e/frame.spec.ts`.
- Details, in one or a few tests on `/`:
  - `page.getByRole('banner')` and `page.getByRole('main')` each have count 1; the banner contains text `APP_NAME` (import it from `src/appName.ts`) (AC1, AC3).
  - The main region is below the banner: its bounding box's `y` ≥ the banner's `y + height` (AC1).
  - The page has no Vite demo content: no text "Vite + React", "count is", and no `img` with alt "Vite logo" (AC1).
  - `getComputedStyle(document.body).margin` is `0px` (AC2).
  - The heading's computed `font-family` contains `Figtree`, and `document.fonts.check('16px Figtree')` is true after `document.fonts.ready` (AC2). If the theme names its font differently, assert the name its `theme.css` declares, and say so in the evidence.
- Done when: `npm run test:e2e` passes locally with only Chromium installed, and passes again under `CI=1`.
- Tests: this task is the tests.
- Depends on: T2.

### Sequence
T1 → T2 → T3, sequential (each needs the last). Total: about 1.5 days (M + S + S). Finish by running exactly CI's sequence on a fresh clone (`git clone`, `npm ci`, the five scripts) (AC5).

## 8. Rollout and rollback

**Feature flag: none for this issue, deliberately.** The frame is the app's first and only UI: there is no previous behaviour for a flag to fall back to, and CI cannot pass without the scripts. Gating the empty frame would leave nothing to show when off. The flag convention for later features, which do have an "off" state, is an environment variable `VITE_FF_<FEATURE>` (Vite exposes `VITE_`-prefixed variables to the client), off unless set to `"true"`. This issue doesn't add any flag code; the first feature that needs one adds it.

Otherwise a plain code change: no migrations, no infrastructure, no deployment target yet. Rollback: revert the merge commit.
